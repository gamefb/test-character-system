Component
=========

**Inherits:** :ref:`Node<class_Node>` **<** :ref:`Object<class_Object>`

**Inherited By:** :ref:`Abilities<class_Abilities>`, :ref:`AttackNearest<class_AttackNearest>`, :ref:`Brain<class_Brain>`, :ref:`CharacterMotor<class_CharacterMotor>`, :ref:`Equipment<class_Equipment>`, :ref:`Faction<class_Faction>`, :ref:`Health<class_Health>`, :ref:`Inventory<class_Inventory>`, :ref:`ItemComponent<class_ItemComponent>`, :ref:`MouseLook<class_MouseLook>`, :ref:`Pool<class_Pool>`, :ref:`Stamina<class_Stamina>`, :ref:`Statuses<class_Statuses>`, :ref:`WeaponSwitch<class_WeaponSwitch>`

Base class for every component: a child node that adds one feature to its parent, the host.

.. rst-class:: classref-introduction-group

Description
-----------

The host also needs a :ref:`ComponentManager<class_ComponentManager>` child. Components register with it by themselves, and through it they find each other, share stats and hear events. A component only runs, between :ref:`_start()<class_Component_private_method__start>` and :ref:`_stop()<class_Component_private_method__stop>`, while everything in :ref:`_requires()<class_Component_private_method__requires>` is present, so components can be added or removed at any time, in any order.

\ **Setting up a host.** Any node can be a host: a :ref:`CharacterBody3D<class_CharacterBody3D>` character, a weapon scene, a crate. Add a ComponentManager and the components as its direct children, in any order:

::

    Player (CharacterBody3D)
        ComponentManager
        Health
        PlayerBrain
        CharacterMotor

\ **What happens, in order.** 

1. The component enters the tree and registers with the manager. From now on its :ref:`_stats()<class_Component_private_method__stats>` can be read. 

2. When the host is ready (after the host's own ``_ready()``), every component whose :ref:`_requires()<class_Component_private_method__requires>` are present gets :ref:`_start()<class_Component_private_method__start>`. A component added later, during play, starts as soon as it's added. 

3. While running, it hears the events it asked for with :ref:`on()<class_Component_method_on>`, and its ``_process()``, ``_physics_process()`` and input callbacks run. Before it starts they don't run at all, so they can use what :ref:`_requires()<class_Component_private_method__requires>` promises without null checks. 

4. :ref:`_stop()<class_Component_private_method__stop>` runs when it leaves the tree, when the host is freed, or when something it requires is removed. Everything connected with :ref:`listen()<class_Component_method_listen>` or :ref:`on()<class_Component_method_on>` is disconnected. 

5. If what it required comes back, :ref:`_start()<class_Component_private_method__start>` runs again. Write :ref:`_start()<class_Component_private_method__start>` and :ref:`_stop()<class_Component_private_method__stop>` so they can run more than once.

If a component can't start, the editor shows a warning on it and the Output panel reports once what's missing. The rest of the host keeps working.

\ **Using components from other code.** Get one with :ref:`of()<class_Component_method_of>`, read stats with :ref:`ComponentManager.stat_of()<class_ComponentManager_method_stat_of>` and send events with :ref:`ComponentManager.notify()<class_ComponentManager_method_notify>`. All three are safe on null or freed nodes and on nodes without components, such as walls.

::

    var health := Component.of(body, Health) as Health  # null if body has no Health.
    if health:
        health.change(-10.0)

\ **Writing your own.** Extend this class and override any of :ref:`_requires()<class_Component_private_method__requires>`, :ref:`_stats()<class_Component_private_method__stats>`, :ref:`_start()<class_Component_private_method__start>`, :ref:`_stop()<class_Component_private_method__stop>` and :ref:`_warnings()<class_Component_private_method__warnings>`. Do setup in :ref:`_start()<class_Component_private_method__start>`, not ``_ready()``: it runs once everything is in place, and never in the editor. This outline shows where each part goes; :ref:`Stamina<class_Stamina>` in ``examples/scripts/`` is a complete one to copy.



::

    @tool  # Optional: shows this component's warnings in the editor.
    class_name Shield
    extends Component

    @export var max_shield := 50.0

    func _requires() -> Array[Script]:
        return [Health]  # Waits until there's a Health beside it.

    func _stats() -> Dictionary[StringName, float]:
        return { &"max_shield": max_shield }  # Statuses can change it by name.

    func _start() -> void:
        listen(manager.stat_changed, _on_stat_changed)  # Disconnected on stop.
        on(&"taking_damage", _on_taking_damage)  # An event on this host. Also undone on stop.

    func _process(_delta: float) -> void:
        pass  # Runs only while the component runs, e.g. to recharge.

    func _on_stat_changed(_stat_name: StringName) -> void:
        pass  # E.g. cut the shield down when max_shield drops.

    func _on_taking_damage(ctx: EffectContext) -> void:
        ctx.mul *= 0.5  # A hit about to land: take half of it.

\ **Rules of thumb.** 

- Don't keep references to other components in variables; :ref:`find()<class_Component_method_find>` them when you need them. They can be removed and added during play, and :ref:`find()<class_Component_method_find>` is cheap. 

- Don't store stat values. Read :ref:`stat()<class_Component_method_stat>` each time, or :ref:`listen()<class_Component_method_listen>` to :ref:`ComponentManager.stat_changed<class_ComponentManager_signal_stat_changed>`; a stored speed ignores every status. 

- Connect with :ref:`listen()<class_Component_method_listen>`, not ``connect()``, and hear events with :ref:`on()<class_Component_method_on>`, so both are undone when the component stops. 

- A component that's optional for yours (used if present) doesn't go in :ref:`_requires()<class_Component_private_method__requires>`. :ref:`find()<class_Component_method_find>` it and check for null.

:ref:`Component<class_Component>` **of**\ (\ node\: :ref:`Variant<class_Variant>`, type\: :ref:`Script<class_Script>`\ ) |static| :ref:`🔗<class_Component_method_of>`

Returns the ``type`` component on ``node``, or null. Safe on null or freed nodes.

Use it from any script: effects, level scripts, UI. Subclasses count, so asking for :ref:`Brain<class_Brain>` finds a :ref:`PlayerBrain<class_PlayerBrain>` or :ref:`AIBrain<class_AIBrain>`. Cast the result to use its members:

::

    var statuses := Component.of(enemy, Statuses) as Statuses

It works on a scene that hasn't been added to the level yet, e.g. to set a spawned enemy's :ref:`Faction.team<class_Faction_property_team>` before ``add_child()``.

Returns the ``type`` component on the same host, or null. Subclasses count. If the host has several, the first is returned. The manager remembers the answer, so calling it every frame is cheap.

Types in :ref:`_requires()<class_Component_private_method__requires>` are never null while the component runs, so in :ref:`_start()<class_Component_private_method__start>` and ``_process()`` you can cast and use them directly:

.. _class_Component_method_listen:

.. rst-class:: classref-method

|void| **listen**\ (\ sig\: :ref:`Signal<class_Signal>`, method\: :ref:`Callable<class_Callable>`\ ) :ref:`🔗<class_Component_method_listen>`

Connects ``sig`` to ``method`` until this component stops. Use it in :ref:`_start()<class_Component_private_method__start>`.

The signal can be on any object: a sibling component, the host, another character or a timer. If that object is freed first, nothing breaks. Connecting the same pair twice before the component stops is an error, as with ``connect()``.

::

    func _start() -> void:
        listen((find(Health) as Health).died, _on_died)
        listen(manager.stat_changed, _on_stat_changed)

.. _class_Component_method_on:

.. rst-class:: classref-method

|void| **on**\ (\ event_name\: :ref:`StringName<class_StringName>`, method\: :ref:`Callable<class_Callable>`, node\: :ref:`Node<class_Node>` = null\ ) :ref:`🔗<class_Component_method_on>`

Calls ``method`` with the event's :ref:`EffectContext<class_EffectContext>` each time ``event_name`` is sent to this host, until this component stops. Use it in :ref:`_start()<class_Component_private_method__start>`.

It's the usual way to react to something that happened to the character:

::

    func _start() -> void:
        on(&"took_damage", _on_took_damage)
        on(&"killed", _on_killed)

    func _on_took_damage(ctx: EffectContext) -> void:
        print("Lost %s to %s damage" % [ctx.amount, ctx.damage_type])

    func _on_killed(ctx: EffectContext) -> void:
        kills += 1  # ctx.target is who died.

The context is null for events sent without one, such as ``started``. It's short for ``listen(manager.event(event_name), method)``: every event is a signal on the :ref:`ComponentManager<class_ComponentManager>`. The built-in events: 

- ``dealing_damage``, ``taking_damage``: a hit about to land. Change :ref:`EffectContext.add<class_EffectContext_property_add>`, :ref:`EffectContext.percent<class_EffectContext_property_percent>` and :ref:`EffectContext.mul<class_EffectContext_property_mul>` to change the damage. 

- ``absorbing_damage``: the same hit with its final number in :ref:`EffectContext.amount<class_EffectContext_property_amount>`. Lower it by what a shield soaks up. 

- ``dealt_damage``, ``took_damage``: the same hit, after it landed. 

- ``giving_healing``, ``receiving_healing``, ``gave_healing``, ``received_healing``: the same for healing. 

- ``died``: the killing blow, or null. ``killed``: the same blow, sent to whoever dealt it. 

- ``ability_cast_started``, ``ability_used``, ``ability_interrupted``: :ref:`EffectContext.origin<class_EffectContext_property_origin>` is the :ref:`AbilityData<class_AbilityData>`. 

- ``started``, ``revived``, ``inventory_changed``: null. 

- The :ref:`CharacterMotor<class_CharacterMotor>` adds one for each mode and move, such as ``walk_mode_entered`` and ``dash_move_started``. 

Send your own with :ref:`ComponentManager.notify()<class_ComponentManager_method_notify>`. Prefer events for "something happened to this character"; for one component's own changes, a signal of its own is simpler. 

Pass ``node`` to hear another host's events instead, e.g. an item listening to its wielder: ``on(&"killed", _on_wielder_killed, wielder)``. A node without a :ref:`ComponentManager<class_ComponentManager>` has no events, so nothing happens.

:ref:`Array<class_Array>`\[:ref:`Script<class_Script>`\] **_requires**\ (\ ) |virtual| :ref:`🔗<class_Component_private_method__requires>`

Component types this one can't work without, e.g. ``return [Brain]``.

.. _class_Component_private_method__stats:

.. rst-class:: classref-method

:ref:`Dictionary<class_Dictionary>`\[:ref:`StringName<class_StringName>`, :ref:`float<class_float>`\] **_stats**\ (\ ) |virtual| :ref:`🔗<class_Component_private_method__stats>`

Numbers this component owns, e.g. ``{ &"max_health": max_health }``. Statuses and items change them with stat modifiers of the same name.

Return the base values, usually your exports, never values with modifiers applied. It's called often, so only build the dictionary. If two components on a host own the same stat, the editor warns and the first one's value is used. Call :ref:`update_stats()<class_Component_method_update_stats>` when one of these numbers changes.

.. _class_Component_private_method__start:

.. rst-class:: classref-method

|void| **_start**\ (\ ) |virtual| :ref:`🔗<class_Component_private_method__start>`

Called once the host is ready and everything this component requires is present. Connect signals with :ref:`listen()<class_Component_method_listen>` here.

It runs after the host's own ``_ready()``, and again after each restart (see :ref:`_stop()<class_Component_private_method__stop>`). Anything it sets up that :ref:`listen()<class_Component_method_listen>` doesn't undo, such as a group, a stat modifier or a spawned node, should be undone in :ref:`_stop()<class_Component_private_method__stop>`.
