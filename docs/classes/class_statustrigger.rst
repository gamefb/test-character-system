.. _class_StatusTrigger_property_event:

.. rst-class:: classref-property

:ref:`StringName<class_StringName>` **event** :ref:`🔗<class_StatusTrigger_property_event>`

The event to react to. Built in: ``dealing_damage`` and ``taking_damage`` (before a hit lands), ``dealt_damage`` and ``took_damage`` (after), ``killed`` when the holder deals a killing blow, ``died`` when something kills the holder, the four healing events (\ ``giving_healing``, ``receiving_healing``, ``gave_healing``, ``received_healing``) and ``ability_used``. :ref:`Component.on()<class_Component_method_on>` lists them all. Send your own with :ref:`ComponentManager.notify()<class_ComponentManager_method_notify>`. Triggers ignore the events that carry no context, such as ``started`` and ``inventory_changed``.

.. _class_StatusTrigger_property_conditions:

.. rst-class:: classref-property

:ref:`Array<class_Array>`\[:ref:`Condition<class_Condition>`\] **conditions** = ``[]`` :ref:`🔗<class_StatusTrigger_property_conditions>`

The trigger only runs if all of these pass. They're checked once, before any effect, so a :ref:`ChanceCondition<class_ChanceCondition>` here rolls once for the whole trigger. The target is whoever :ref:`affects_other<class_StatusTrigger_property_affects_other>` picks, and a :ref:`HitCondition<class_HitCondition>` reads the hit that set the trigger off.

.. rst-class:: classref-property

:ref:`bool<class_bool>` **react_to_statuses** = ``false`` :ref:`🔗<class_StatusTrigger_property_react_to_statuses>`

Also react to events caused by statuses, such as burn ticks. Use for shields and damage modifiers only: two damaging triggers with this on would set each other off, until the chain is cut at :ref:`EffectContext.MAX_DEPTH<class_EffectContext_constant_MAX_DEPTH>`.
